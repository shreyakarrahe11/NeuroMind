# Binary integration handoff

This project now also includes the operational changes and acceptance checklist in `PRODUCTION_RUNBOOK.md`. The speech encoder's artifact hash is carried from embeddings through fusion training into the patient recording and verified before inference. Re-run the updated Colab notebook and apply Alembic revision `0009_speech_model_lineage` when upgrading from the previous ZIP.

## Implemented in this package

- Two labels end to end in active model manifests, fusion training, validation, API outputs and result screens: **Non-Dementia** and **Dementia**.
- The UI only opens results after successful inference and shows an error and retry when an artifact is absent. A report provider failure leaves the real prediction visible.
- A report generated by either backend route gets fixed, class-specific **What to do** and **What to avoid** steps after the Gemini response. Higher risk says to arrange a qualified doctor's assessment; both outcomes explain the limits of screening and discourage changing medicines based on the app. The result screen includes short doctor advice.
- Three Drive PDFs are bundled in `knowledge_base/`. The admin RAG route indexes this directory into PostgreSQL and, when configured, Chroma. Local parsing verified that all three produce text and about 958 bounded text chunks; the live index was not run.
- The older `best_simple_bilstm_model.pth` is retained in `source_checkpoints/`. It is an uninstalled research baseline, with a Colab export script provided; do not point `SPEECH_MODEL_PATH` to the source checkpoint.

## Required to finish live integration

1. In Colab, train and validate the binary speech model from real audio with the bundled notebook. Keep its exported Wav2Vec2 backbone and patient embeddings. The old baseline exporter is available only as an experimental alternative; it outputs 256 values and needs fusion retraining. The trained attention speech pipeline outputs 128 values. **Never mix them.**
2. Obtain matching real patient rows for the exact 15 website memory, attention and lifestyle inputs. Inspect scales, label definitions and split leakage, then run the binary fusion notebook. The previously saved `.keras` model takes 768 speech features and synthetic auxiliary rows, so it is not a compatible substitute.
3. Install the validated speech and fusion TorchScript outputs with `training.install_phase1_artifacts`, configure `backend/.env` and run `npm run models:status`. Confirm speech embedding dimensions and feature ordering, held-out dementia recall, fusion predictions and SHAP before allowing production assessments.
4. Configure PostgreSQL and run migrations; configure Clerk and Gemini server-side keys. Run `npm run setup:ai` and the admin `POST /api/v1/rag/index` route against the bundled PDFs. Confirm the index reports semantic readiness and retrieved chunks are cited in actual reports.
5. Test a patient recording and questionnaire through result → report → authenticated PDF → patient-selected doctor share → doctor review. Check both risk labels and the fixed doctor advice. No real credentials or running PostgreSQL/Clerk/Gemini service were available in this workspace.

## Verification in this workspace

- Python source compiled; deterministic high- and low-risk follow-up checks passed; invalid labels raise an error.
- All three PDF files extracted nonempty text (about 728,000 characters and 958 current text chunks total).
- A standalone PDF renderer smoke check produced a readable PDF containing the high-risk doctor guidance; it used stub report records and does not verify the authenticated API or Gemini.
- The Colab notebooks and actual trained model have **not** been executed on a GPU here. SHAP, Gemini, PostgreSQL RAG indexing and the full browser flow are **unverified**.
- A valid result requires a compatible trained binary speech model and a fusion model trained from aligned real features. Until then the API should report that the model is pending.
